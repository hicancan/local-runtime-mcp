# lrmcp 正演沉淀池（Evolution Backlog）

> 原则：**只留未解决的真问题，修完发版即删**（历史交给 Git 与 `docs/releases/`）。  
> 思维：**从根因彻底重构与正演**，不做表面补丁、特例兜底或冗余兼容层。

## 录入标准（强信号门控）

仅在实际调用 `lrmcp` 过程中遇到以下情况时，在不打断当前主任务的前提下顺手追加一条精简记录；正常顺手使用时绝不记流水账：

1. **真实报错或静默算错**（含跨平台 / Windows 边界 / 时区 / 编码 / 并发竞态）
2. **异常卡顿、挂起或明显资源浪费**（如超时、多余 I/O、内存/存储膨胀）
3. **被迫绕路或契约不清**（文档/提示与真实签名或返回结构不一致）
4. **明确想到更简洁、更正交的底层设计或 API 抽象**

## 条目格式

```markdown
### [YYYY-MM-DD] 一句话概括核心问题或正演方向
- **现象 / 证据**：实际触发条件、耗时/报错或审计 `event_id`
- **根因判断**：底层卡在什么机制上
- **理想正演方案**：如何从架构或引擎根因彻底解决（而非打补丁）
```
