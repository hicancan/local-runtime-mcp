# Local Runtime MCP v14.0.0

One Local Runtime now serves reusable webpage tools, authorized web applications
and browser-backed models. These entrances share the existing browser connection
and resource owner; they add no Node server or cloud project.

## File-based capabilities

Each capability is one same-named JSON definition and JavaScript implementation.
`capabilities/deepseek/start.json` and `start.js` register `deepseek.start`.
Definitions declare exact target origins, input/output schemas and actual effects;
the Host validates the whole directory before publishing the tools through MCP.
There is no separate registration manifest.

The release includes DeepSeek start/read/stop and a read-only MOOC course-outline
example. MOOC remains an application of the general capability mechanism.

## Web applications

The browser SDK calls named capabilities and models through the same extension.
The extension supplies the real top-level sender identity. Exact-origin owner
grants determine what each website may see and call; webpages receive no runtime
credential, arbitrary-script interface or target-tab selector.

The shared SDK is attached to this release as an installable `.tgz` and is used
by StuDev. Streaming, public error codes, cancellation and explicit conversation
closure use one protocol across the SDK, extension and Host.

## Browser models and conversations

The public loopback listener also serves `/v1/models` and
`/v1/chat/completions`, authenticated by an independent model-only key. That key
cannot authenticate machine control. Direct browser-origin HTTP calls are refused;
authorized websites use the extension bridge.

`conversation_id` is mandatory. The first request creates one owned webpage
conversation; subsequent messages and tool results append to that same page.
Caller scope, model and conversation identity isolate ownership. Explicit history
branches use new IDs, while cancellation and an explicit retry retain the original
conversation. A retry of an already validated answer returns that same answer and
tool-call IDs without another model submission. Closing a missing/already-closed
conversation is idempotent and does not disclose other callers' resources.

Each generation carries a separate turn identity, preventing a late read or stop
from observing or cancelling the wrong response. Source failures and interrupted
generation are reported without automatic replay. Website conversation history is
not deleted when Local Runtime closes its own tab.

Model tool requests must be a complete structured response and pass tool-name,
argument-schema and choice validation before becoming `tool_calls`. The runtime
never executes them. User-facing answer-format instructions apply inside the
transport's `content` field, preserving the structured protocol on final answers.

## Harness integration

`integrations/harness` is a small plugin using Harness's supported `LlmAdapter`
interface. Harness retains its actual agent loop, tools, permissions and sessions.
Its real Session ID is forwarded as `conversation_id`; the adapter does not
invent a shared fallback session or advertise unsupported token controls.

The browser endpoint explicitly rejects unsupported sampling/token limits,
images and response-format controls. It is not the official DeepSeek API and
does not claim the entire OpenAI API contract.

## Updating

Replace the executable and bundled capability directory while preserving private
configuration. Regenerate the installed extension with `lrmcp setup browser`, then
reload that same extension. Configure separate model credentials and explicit web
grants; see [tools, webpages and models](../models.zh-CN.md).

Clients using the model endpoint must supply stable `conversation_id` values and
only supported request fields. Existing MCP authentication and private tunnel
boundaries remain separate. The host, extension manifest and worker version are
generated from `browser-extension/package.json`.
