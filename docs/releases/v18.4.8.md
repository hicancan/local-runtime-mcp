# v18.4.8 — Bidirectional Multimodal Files, Unshadowed Native Vision & Self-Healing Extension Sync

## Highlights

- **Unshadowed native `ImageContent` delivery on `run` and `wait`**: removed `outputSchema` and `StructuredContent` from `run` and `wait` so `CallToolResult.Content` delivers `[ImageContent..., TextContent(JSON)]` directly. Remote MCP connectors that previously skipped `ImageContent` whenever `structuredContent` was present now forward both image pixels and structured execution JSON cleanly without exposing any public image URLs.
- **Bidirectional inbound file transfer (`_meta["openai/fileParams"]`) on `run`**: added an optional `files` parameter on `run` declaring the standard four-field file object schema (`download_url`, `file_id`, optional `mime_type`, `file_name`) and `_meta["openai/fileParams"] = ["files"]`. Host-uploaded or generated files (images, PDFs, documents) are downloaded concurrently with strict HTTPS/non-private-IP SSRF protection (preserving `HTTPS_PROXY` and TUN fake-IP compatibility), deduplicated by `file_id`, staged atomically under `lrmcp-inbound/`, redacted in audit logs, blocked under read-only grants, and bound inside JS as globals `inputFiles` and `inputFile`.
- **Singleflight browser CDP dial coordination**: concurrent `browser.connect()` / `resolveClient()` calls on the same browser entry now wait on the single in-flight WebSocket handshake instead of returning spurious duplicate-connection errors under contention.
- **Self-healing browser extension config sync**: starting the daemon now automatically synchronizes an adjacent `browser-extension/runtime_config.js` from `local-runtime-mcp.yaml`, and the extension falls back cleanly to `packagedConfig` when `chrome.storage.local` holds an empty token/address string.
