# Local Runtime MCP v12.0.0

One machine runtime can now serve OpenAI and Cloudflare connections together. The same 21 tools share process sessions, browser instances, file commit coordination, and desktop control across entrances.

## Connections

```powershell
lrmcp serve --transport stdio
lrmcp serve --transport http
lrmcp serve --transport http --tunnel openai --tunnel cloudflare
```

The transport is explicit and tunnel selection is repeatable. OpenAI keeps a private authenticated HTTP hop; direct HTTP and Cloudflare use the configured public-auth origin. Individual entrance failures leave the other entrances and shared runtime available.

This release replaces the positional `serve stdio` / `serve http` and top-level `tunnel` commands with the commands above. Existing portable provider and browser settings remain in `local-runtime-mcp.yaml` beside the executable.

## OAuth

Public HTTP can use static Bearer authentication or owner-approved OAuth authorization. OAuth provides discovery, preregistered clients, Authorization Code with S256 PKCE, exact callback and resource matching, rotating refresh tokens, revocation, and issuer identification in authorization responses.

```powershell
lrmcp setup oauth --client-name gemini --redirect-uri "https://client.example.com/callback"
lrmcp setup oauth --show
```

Replace the example callback with the exact URI supplied by the client. Setup selects OAuth mode and stores client credentials and an owner approval key in the portable configuration. Setup deliberately displays these credentials locally. The owner explicitly approves full machine access on the authorization page. Grants live in memory, so restarting the runtime requires reauthorization.

## Verification

Regression tests cover shared state across independent private/public HTTP entrances, continued process output after one entrance closes, OAuth-to-MCP authorization, credential separation, and raw HTTP PNG content with structured metadata. The Windows browser fixture covers multiple profiles, idle WebSocket lifetime, and reconnection after a host outage. Desktop capture smoke tests are available for interactive Windows sessions.

Actual third-party host connection and visual-model consumption are verified in the client. See the [connection guide](../connections.md) and [Chinese guide](../connections.zh-CN.md) for setup and cross-provider acceptance.
