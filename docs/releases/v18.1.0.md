# v18.1.0 — Strict SDK Contracts, Built-in `help()`, & REPL Ergonomics

`v18.1.0` tightens the developer and model ergonomics of the v18 runtime based on real-world blind MCP usage:

- **Strict SDK Validation (Zero Silent Option Drops)**:
  - Added missing `json:"snake_case"` struct tags on `filesystem` (`ReadTextOptions`, `WriteTextOptions`, `PatchTextOptions`) and `image` (`ReadOptions`), fixing silent option ignoring on `fs.read` line ranges and enforcing `expected_sha256` optimistic locks on `fs.write`.
  - Added `end_line` support alongside `line_count` in `fs.read(path, { start_line?, end_line?, line_count?, max_bytes?, with_sha256? })`.
  - Enforced strict type checking, `DisallowUnknownFields`, and extra positional argument rejection across `proc`, `fs`, `browser`, `tab`, `locator`, `desktop`, `img`, and `caps` — every mismatch fails fast with the exact valid signature.
- **Self-Documenting `run` Contract & Zero-Cost `help(topic?)`**:
  - Moved the concise, copy-paste-ready SDK signature sheet directly into `run`'s tool description and trimmed `server.instructions` to 3 lines so site capability tools are no longer bloated by repeated SDK summaries.
  - Added synchronous `help(topic?)` inside the JS VM (`help()`, `help("fs.read")`, `help("browser")`, `help("tab")`, etc.).
- **REPL Auto-Return & Clearer Telemetry**:
  - Bare final expressions in `run` (e.g. `await browser.status()` or `help("fs")`) now auto-return in `cell.value` while hoisted declarations remain quiet in VM state.
  - Added top-level `sub_op_errors` summary count to `CellResult` (including strict parameter-validation rejections caught via `Promise.allSettled`) and wired `caps.list()` into `sub_ops` tracking.
  - Made `session(done)` return the real `closed_tabs` count (explicitly `0` when none) from `CloseSession`.
  - Shortened initial CDP approval dial timeout to 12s and made `awaiting_approval` fail fast on follow-up calls until `browser.connect(...)` is retried after clicking Allow.
  - Clarified that single-shot read-only queries can call `run` directly without `session(start/done)` ceremony.
