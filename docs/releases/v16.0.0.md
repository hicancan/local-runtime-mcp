# Local Runtime MCP v16.0.0

Unified detached user-session daemon, hot-pluggable remote wires with automatic
TTL leases, live per-wire remote grants, bidirectional extension control panel,
and a pure capability core.

## What changed

### 1. Detached user-session daemon & stateless `stdio` thin proxies
- `lrmcp` now runs as one persistent user-session daemon (`lrmcp daemon` foreground,
  or `lrmcp start` / `stop` / `status` background management) in the interactive
  desktop session (never Windows Session 0).
- Every local MCP client configured with `lrmcp serve --transport stdio` attaches
  concurrently as a pure stateless thin proxy over `127.0.0.1:9317/mcp/attach`.
  When no daemon is running yet (and `local.token` is configured), the first
  `stdio` client automatically spawns the detached daemon in the background
  without tying the daemon's lifetime to that IDE window. Closing the first IDE
  never disconnects other local clients or the browser bridge.
- Zero-config `lrmcp serve --transport stdio` (without `local.token`) continues
  to run an isolated in-process runtime for one-off smoke testing.

### 2. Hot-pluggable remote wires with optional TTL leases
- Remote tunnels (`openai`, `cloudflare`, `http`) are no longer static startup
  flags that force a daemon restart.
- Plug or unplug any wire live without interrupting local clients, running
  process sessions, or browser tabs:
  ```powershell
  lrmcp tunnel up openai --ttl 2h
  lrmcp tunnel down openai
  lrmcp tunnel up cloudflare
  lrmcp tunnel down all
  ```
- When no remote wire is active, the daemon has zero external exposure surface.
- The authenticated `L` browser extension panel displays live daemon status,
  attached local session count, remote wire toggles, and a one-click emergency
  desktop stop button.

### 3. Live per-wire remote grants (`grants.remote`)
- Remote wires (`openai` and `http`/`cloudflare`) now obey independent owner
  grants under `grants.remote`:
  ```powershell
  lrmcp grant remote openai --read-only
  lrmcp grant remote http --tool filesystem_read_text --tool browser_snapshot
  ```
- Updating a remote grant immediately reconciles that wire's published MCP tool
  catalog and emits `tools/list_changed` with zero restart.

### 4. Pure capability core (removal of `modelapi` and Harness adapter)
- The browser-DOM OpenAI `/v1/chat/completions` chat proxy (`internal/modelapi`),
  the `models:` configuration block, `models.*` web SDK methods, and
  `integrations/harness` have been removed from the core runtime.
- `lrmcp` and its paired Chromium extension now focus exclusively on machine
  capabilities (Process, Filesystem, Image, Rust WGC/UIA Desktop, CDP Browser),
  distilled Web MCP capabilities (`capabilities/<site>/`), and local App MCP
  bindings (`capabilities/<app>/`).
- Any higher-level browser-model proxy can live outside the kernel as a standard
  consumer of the distilled webpage capabilities (`deepseek.start/read/stop`).

## Breaking changes & migration
- Remove `models:` from `local-runtime-mcp.yaml`, along with `models:` fields
  under `grants.web[]` and `grants.clients[]`.
- Replace `lrmcp serve --transport local` with `lrmcp start` (background) or
  `lrmcp daemon` (foreground).
- Replace `lrmcp serve --transport http --tunnel openai` with `lrmcp tunnel up openai`
  (or `lrmcp daemon --tunnel openai` in foreground).
- Run `lrmcp setup browser` and reload the browser extension so its version
  matches `16.0.0`.
