# Local Runtime MCP v13.0.0

Desktop control now works alongside the person at the computer. Agents see every display and window, read complete UI Automation trees, and operate controls through their patterns without the pointer, the keyboard or the foreground window. Physical input remains available under a control token, shown by a small pill instead of a window outline.

## Displays and windows

`computer_targets` returns displays with their bounds, work areas, scale and primary flag, and windows with process, class, visible frame, normal/minimized/maximized state and display. Frames exclude the invisible resize borders, so a maximized window reports exactly its work area. Cloaked windows are no longer listed. Results can be filtered by process ID, title or executable name.

## Observation

`computer_state` observes one window, one display or every display, and can crop a region, skip pixels, or draw the pointer (now off by default). Window trees are fetched in a single cached cross-process request and include text, AutomationIds, classes, values and toggle, selection and expansion states, depth and parent, disabled, offscreen and focused flags, and the supported patterns. Elements can be filtered by name, AutomationId and role and paged. Element and display observations no longer require desktop control; their refs drive semantic actions.

`computer_wait` is new: it polls a window's tree without pixels until a matching element is present or absent.

## Actions

`computer_action` gains semantic kinds that act through UI Automation patterns without desktop control: `invoke`, `toggle`, `select`, `expand`, `collapse`, `set_value`, `scroll_into_view` and `scroll_by`. Refs are checked against the element's runtime identity before use. `place` moves or resizes a window to a visible frame, restores it or minimizes it without activating it, including across displays of different scale. Physical kinds keep their token, foreground and state checks.

## Indicator

The blue outline, position marker and title strip are replaced by a translucent pill at the bottom of the display being worked on, shown only while physical control is held. Clicking it stops the workflow. It is excluded from capture and never takes focus.

## Breaking changes

- `computer_targets` returns `{displays, windows}`; window bounds are visible frames.
- `computer_state` returns refs without `control_id`, reports `elements_total`, `has_image`, `scale` and `display_id`, and omits the pointer unless `cursor` is set.
- `computer_action` no longer requires `control_id` for semantic kinds and `place`; `set_value` acts without the foreground.

## Updating

Replace the release package while preserving `local-runtime-mcp.yaml`, then restart the runtime. Reload an installed browser extension after regenerating it with `lrmcp setup browser`.
