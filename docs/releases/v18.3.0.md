# v18.3.0 — Embedded IANA Timezones (`Intl.DateTimeFormat`) & Full `tab.eval(scriptOrFn, ...args)`

`v18.3.0` eliminates the final two ergonomics and correctness edge cases in the embedded JS runtime:

- **Embedded IANA `tzdata` + Go-Backed `Intl.DateTimeFormat` & `Date.prototype.toLocale*String` (`internal/jsrt/intl.go`)**:
  - Embeds Go's standard `time/tzdata` directly inside the single binary so `timeZone` works offline on Windows and minimal Linux hosts with zero external files.
  - Supports `Intl.DateTimeFormat` (`format`, `formatToParts`, `resolvedOptions`, callable with or without `new`) and patches `Date.prototype.toLocaleString`, `toLocaleDateString`, and `toLocaleTimeString`.
  - Honors IANA time zones (including automatic DST transitions such as `America/Los_Angeles` PDT/PST alongside fixed-offset zones like `Asia/Shanghai`) and fails fast with `RangeError` on invalid or empty `timeZone` values instead of silently falling back to the host OS timezone.
- **Full Playwright-Grade `tab.eval(scriptOrFn, ...args)` (`internal/jsrt/sdk.go`)**:
  - Preserves strict backwards compatibility for `tab.eval(script)` strings (rejecting extra arguments when passing a raw string).
  - Supports passing plain/arrow/async/shorthand JS functions with arbitrary JSON-serializable arguments (preserving `undefined`, `null`, `Date`, `NaN`, `Infinity`, and nested structures across the browser VM boundary), rejects native/bound functions and non-serializable arguments fast, and appends a clear cross-VM argument-passing hint when page execution throws a `ReferenceError`.
