# v18.4.7 — Pure ImageContent Wire Parity & Unified Desktop `ref_id`

## Highlights

- **Pure `ImageContent` wire parity for `emitImage`**: when `run` or `wait` emits one or more images via `emitImage(...)`, `CallToolResult.Content` now carries pure native `ImageContent` blocks (`Content[0].type == "image"`) while `StructuredContent` carries the complete `CellResult` JSON — matching `v17` image delivery wire semantics so MCP hosts do not shadow emitted image blocks behind a leading duplicate `TextContent` block.
- **Unified desktop `ref_id` naming across Go, Rust UIA, and JS SDK**: renamed `desktop.action()`'s `element_ref` input parameter to `ref_id` to match `desktop.state()` / `desktop.wait()`'s `elements[].ref_id` output across the Go runtime, embedded Rust Windows UI Automation worker, `help("desktop")`, and tool schemas.
