# v18.1.1 — Strict Chromium CDP State-Machine Alignment

`v18.1.1` resolves three real-world Chromium CDP state-machine edge cases surfaced during live Edge 158 testing:

- **Zero-Race `browser.open` & Complete Main-Document Network Capture**:
  - `browser.open(url)` now creates `about:blank`, attaches and enables `Page`/`Network`/`Runtime`/`Log`/`DOM` first, then navigates via `Page.navigate` while waiting on `Page.loadEventFired` (eliminating the `about:blank` `readyState == "complete"` race).
  - Promoted navigation requests sharing `Page.frameNavigated.frame.loaderId` into the new `NavigationSeq`, ensuring `tab.network()` always captures the main `Document` request (and redirect hops) on both initial open and reload.
- **`tab.css()` Automatic DOM Initialization & User-Agent Rules**:
  - Automatically runs `DOM.enable` + `DOM.getDocument({ depth: 0 })` before `DOM.pushNodesByBackendIdsToFrontend`, eliminating `CDP -32000: Document needs to be requested first`.
  - Preserves author rules first and includes `user-agent` matched rules (capped) so elements styled by browser defaults immediately report matched rules.
- **Browser-Native Performance API Metrics in `browser.traceStop`**:
  - When `traceStart` targets a tab (`tab_id`), `traceStop` reads exact kernel-computed `ttfb_ms`, `fcp_ms`, `lcp_ms`, `dcl_ms`, `load_ms`, and `cls` directly from the tab's Web Performance API (`metrics_source: "page_performance_api"`) alongside the lossless raw Chromium trace file, and restores `Network.setCacheDisabled(false)` on stop.
  - Browser-wide trace analysis now locks milestone matching to the latest navigation's `(pid, frame)` to prevent cross-frame timestamp inversions.
