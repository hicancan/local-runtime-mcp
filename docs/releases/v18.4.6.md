# v18.4.6 — Zero-Plaintext Persistent OAuth Grants & Seamless Remote Connector Continuity

## Highlights

- **Zero-plaintext persistent OAuth grants (`lrmcp-oauth-grants.json`)**: active OAuth grant families, access token digests, and refresh token digests (including rotated `used` flags for RFC 9700 replay detection) are now atomically persisted beside the runtime configuration using SHA-256 digests only (mode `0600`, zero plaintext tokens on disk). Upgrading binaries, rebooting the host, or toggling Cloudflare tunnels no longer logs out connected remote MCP clients (such as ChatGPT or Gemini). Rotating `owner_token` or a client's `client_secret` automatically invalidates the affected persisted grants on load.
- **Sliding 30-day refresh lifetime**: every legitimate `refresh_token` rotation extends the grant family's inactivity window by 30 days, keeping actively used remote connectors continuously authenticated while still expiring abandoned grants cleanly.
- **Improved OAuth 2.1 / RFC 8414 remote client compatibility**:
  - `grant_type=refresh_token` now permits omitting the optional `resource` parameter (while still rejecting any mismatched non-empty target), preventing silent background refresh failures across strict OAuth 2.1 clients.
  - Added the RFC 8414 path-insertion discovery alias `/.well-known/oauth-authorization-server/mcp` alongside `/.well-known/oauth-authorization-server`.
