# v18.4.4 — Dual-Subsystem Occluded-Tab Wake State Machine

## Highlights

- **Root-cause fix for occluded background-tab `mouseMoved` 5 s stall and `mouseWheel` hang**: Chromium throttles hidden background tabs across two orthogonal subsystems—Viz `CopyFromSurface` (woken by `Page.startScreencast` / `IncrementCapturerCount`) and Blink's main-thread `BeginMainFrame` / `rAF` input pipeline (woken by `Emulation.setFocusEmulationEnabled(true)`). Without waking Blink's main thread, rAF-aligned continuous inputs (`mouseMoved` inside `click`/`hover`/`drag`, and `mouseWheel` inside `scroll`) hit Chromium's 5 s input ACK timeout or stalled indefinitely; conversely, holding focus emulation enabled across static-page `Page.captureScreenshot` stalled repeated screenshots for 4–10 s.
- **Unified per-tab `bgModeInput` / `bgModeCapture` state machine**: replaced `ensureBgCapturer` with serialized `ensureBgMode` sharing one 15 s idle release timer and immediate release on `MarkHandoff`, close, detach, or explicit `screencastStart`. Consecutive background clicks, fills, and scrolls hold input mode with zero per-action toggling (`5009 ms → 2–11 ms` clicks, `36 s+ → 3–5 ms` scroll), while `screenshotTab` cleanly drops focus emulation before `Page.captureScreenshot` (`19–40 ms` repeated captures) without switching tabs or stealing OS focus.
