# Local Runtime MCP v12.0.1

Owner-approved OAuth connections now complete their browser callback chain in Chromium, including callbacks that redirect onward to a client application.

## OAuth callback compatibility

The consent page keeps its fixed same-origin form action, script and frame restrictions, and no-store responses. Its Content Security Policy permits the browser to follow the authorization response through the registered callback and the client's subsequent navigation. A same-origin referrer policy preserves the form's Origin while suppressing Referer on cross-origin callbacks; protocol and error responses retain no-referrer. Exact callback registration, browser-bound consent, Origin checks, owner approval, S256 PKCE, client authentication, token rotation, and revocation retain their existing contracts.

## Browser regression coverage

An isolated Edge profile exercises the production consent page with fixture-only credentials. Tests cover:

- Approval and token exchange using both client authentication methods.
- Refresh token rotation after authorization.
- A callback and final client page on two distinct origins.
- Cancellation, preserving state and issuer without issuing an authorization code.
- Incorrect owner approval followed by a successful retry.

CI and the release build run these real-browser regressions three times. Protocol tests continue to cover invalid callbacks, cookies, Origins, PKCE, expired requests, and replay rejection.

## Updating

Replace the release package while preserving `local-runtime-mcp.yaml`, then restart the runtime and begin a new client authorization. Registered client credentials and provider settings remain in the portable configuration. Reload an installed extension after regenerating it with `lrmcp setup browser`.

Actual Gemini account acceptance is checked in Gemini after updating; the regression fixtures do not use third-party accounts or operator credentials.
